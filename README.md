# FinReport-Core

**用一段可重跑的規則，取代「月底手動合併報表」這件事。純規則、零 LLM、可完全離線執行，資料不離開你的電腦。**

這不是一個 AI 產品。這是一個會計／行政報表的正規化與合併引擎，設計前提是：
**數字錯一筆的代價，遠高於慢一天。**

---

## 它解決什麼

多來源報表（出單明細、帳目、對帳表）在月底要合併成一份總表，人工做的時候會遇到三件事：

1. **主鍵不一致**：保單號碼有的帶空格、有的帶全形字元，合併時對不上
2. **金額欄位混進文字**：一筆「待確認」就讓整欄加總失效，而且沒人發現
3. **重複資料**：同一筆被匯入兩次，總額多算一次，報表看起來正常但數字是錯的

這三件事的共同點是：**錯了不會報錯，只會靜靜地產出一份看起來正常的錯報表。**

本引擎的處理方式是：遇到這三類情況**停手，不產出正式報表**，只產出一份稽核清單告訴你第幾列、哪個欄位、為什麼被擋。

## 實測數據（可自行重跑驗證）

| 指標 | 標準 | 實測 |
|---|---|---|
| 執行時間 | 1,000 筆 ≤ 15 秒 | **0.02 秒** |
| 欄位計算正確率 | 100% | **100.00%**（8 欄位 × 1,000 列，0 不符） |
| 缺主鍵 | 阻斷並列稽核 | **通過，未產出正式報表** |
| 金額非數值 | 阻斷並列稽核 | **通過，未產出正式報表** |
| 主鍵重複 | 阻斷並列稽核 | **通過，未產出正式報表** |

期望值由**獨立產生器**提供，不是拿引擎自己的輸出去比對自己。

## 自己驗一遍（三步）

```bash
pip install openpyxl
python3 tools/make_demo_data.py                  # 產生去識別化測試資料
python3 -m finreport.cli --config config/demo_config.json --audit output/Audit_Error_Log.csv
python3 tests/test_acceptance.py                 # 18 項驗收，含三類異常阻斷與斷網測試
```

## 為什麼是純規則，不是 AI

金融與保險業的資安審查只問一句話：**資料會不會上傳雲端。**

只要架構裡有任何一個 LLM API 呼叫，這個案子就必須走資安審查、簽 DPA、做 PII 評估，時程從兩週變成三個月。
本引擎把這些全部拿掉：金額、日期、主鍵、借貸平衡都是可歸責的確定性規則。**錯了會停，不會猜。**

代價是它不會處理模糊情況。這是刻意的：模糊的部分留給人判斷，機器只負責不會錯的部分。

## 適用與不適用

**適用**：固定樣板的報表合併、多來源對帳、月底彙總、需要稽核軌跡的場合、資料不可外流的環境。

**不適用**：需要語意判斷的場合（例如從自由文字中萃取金額）、需要即時串接多個 SaaS API 的場合、沒有固定樣板的場合。
