# 資料治理怎麼做（我們的做法，可直接照抄檢查）

這份文件寫的是我們在專案裡怎麼處理「別人的資料」。寫成可檢查的清單形式，因為治理不是宣示，是能被外部驗證的動作。

---

## 一、第一原則：資料不出門

**做法**：架構裡不允許出現任何雲端 LLM 呼叫或第三方資料上傳。
**檢查方式**：封鎖 socket 後跑完整流程，仍能通過即證明。

```bash
python3 tests/test_acceptance.py   # 含 D1 斷網測試
```

**為什麼**：只要資料會上傳雲端，就必須走資安審查、簽 DPA、做 PII 評估，時程從兩週變三個月。拿掉上傳，這些全部消失。
**代價**：不處理模糊情況。模糊的部分留給人，機器只做不會錯的部分。

## 二、開發階段：用假資料，不用真資料

**做法**：
1. 用產生器造合成資料（`tools/make_demo_data.py`），欄位結構與真資料相同，內容全假。
2. 產生器同時產出**期望值檔**（`samples/expected.json`），與引擎輸比分開存放。
3. 期望值不得取自引擎自己的輸出，避免循環驗證。

**檢查方式**：`expected.json` 由產生器寫出，時間戳早於引擎執行；兩者分屬不同程式。

## 三、真資料進來時：三個動作，順序不能換

1. **最小化**：只取這次工作需要的欄位。不需要身分證字號、地址、電話的，就不進資料集。
2. **去識別化**：姓名換代號、證件號碼與保單號碼做可逆替換，對照表**不放在同一台機器**。
3. **落地隔離**：原始檔只放在指定工作目錄，處理完即刻刪除，不留副本、不上傳、不進版本控制。

**檢查方式**：`git status` 無未追蹤的資料檔；工作目錄在交付後為空。

## 四、錯誤處理：停手，不猜

**做法**：遇到無法確定的資料（缺主鍵、金額非數值、主鍵重複），**停止產出正式報表**，只產出稽核清單：第幾列、哪個欄位、原始值、為什麼被擋。

**檢查方式**：三類異常各自跑一次，確認無正式輸出檔，僅有 `_blocked_*_audit.csv`。

**為什麼**：錯誤的報表比沒有報表危險，因為沒有人會去查一份「看起來正常」的數字。

## 五、可稽核：每一份交付都要能重跑

每一份交付附三樣：
1. **稽核清單**（哪些資料被擋、為什麼）
2. **驗收證據**（測了幾項、幾項通過、怎麼重跑）
3. **檔案雜湊清單**（sha256 + 檔案清單），確認交付物沒被動過

**檢查方式**：拿到交付包的人在不問我們的情況下，能自行重跑並得到相同結果。

## 六、憑證與權限

1. 憑證只用環境變數注入，**不寫進程式、不寫進文件、不進版本控制**。
2. 一支憑證只給一個用途，不共用。
3. 需要提升權限時，先報方案再動，不自行擴大範圍。
4. 對外服務一律用最小權限，不用管理員帳號跑日常任務。

## 七、資料保留與刪除

| 資料類型 | 保留 | 刪除時機 |
|---|---|---|
| 合成測試資料 | 專案期間 | 交付後隨專案封存 |
| 客戶原始資料 | 處理期間必要天數 | 交付驗收後即刻刪除，並回報刪除結果 |
| 稽核清單 | 保留，不含原始值 | 只保留「為什麼被擋」，不保留敏感原值 |
| 交付物雜湊 | 永久 | 作為事後查核依據 |

## 八、事故處理

1. 發現資料外洩或誤用：**先停流程，再通報**，不通報不算處理。
2. 通報內容固定三項：影響範圍、已做的處置、需要對方配合的事。
3. 事後補一份「怎麼發生的、怎麼防下一次」，不寫檢討文。

## 九、這份文件怎麼被檢查

- [ ] 斷網可跑（第一節指令）
- [ ] 期望值獨立產生（第二節）
- [ ] 版本控制無資料檔（第三節）
- [ ] 三類異常皆停手（第四節）
- [ ] 交付附稽核＋驗收＋雜湊（第五節）
- [ ] 程式碼內無憑證明文（第六節，可用關鍵字掃描）
- [ ] 有刪除紀錄（第七節）

七項全部可被第三方獨立在半小時內驗完。做不到的項目就不要寫進合約。
